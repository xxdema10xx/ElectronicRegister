# Proposta di completamento del refactoring delle responsabilità

## Punto di partenza e perimetro

La regressione del codice attuale è superata: 587/587 unitari e 1420/1420 integrazione, 0 Failed e 0 Skipped. [Verifica delle TRX](validation/responsibility-host-regression-verification.json). I 1418 casi integration precedenti sono presenti con la stessa molteplicità; si aggiungono le due prove filesystem. Questo risultato chiude il blocco della regressione corrente. Non fornisce una baseline SQL verde del commit precedente né completa l'analisi delle responsabilità.

Questa è una proposta, senza modifiche applicative, migrazioni, commit o push. Le fasi seguenti richiedono successivi interventi espliciti; nessuna istanza MySQL esistente viene riutilizzata o alterata da questa revisione.

## Condizione di completamento

Il refactoring sarà completabile quando il legacy avrà una decisione eseguita per ogni componente, il debito architetturale sospeso sarà risolto o motivatamente mantenuto, l'analisi semantica avrà copertura documentata e le verifiche del codice finale saranno verdi. Il verde odierno resta il riferimento della regressione corrente, senza essere una prova esaustiva di equivalenza semantica o assenza di codice morto.
