# Portable local test database through MT-5D

Prerequisites: Windows, PowerShell 5.1+, Python 3.10+, .NET 10 SDK and the supported
MAMP MySQL **5.7.24** binaries (mysql, mysqld, mysqladmin, mysqldump). Allow at least
2 GiB free space. Install these tools separately; never copy another server's datadir.
MariaDB/MySQL 8 are not automatic substitutes.

From a clone containing the reviewed source candidates, at the repository root:

```powershell
python tools/verify-project-artifacts.py
$password = Read-Host 'New private password for the isolated test root' -AsSecureString
./tools/setup-local-test-db.ps1 -MySqlBin C:\MAMP\bin\mysql\bin -CreateInstance -ConfirmIsolatedTest -Password $password
./tools/test-local.ps1 -MySqlBin C:\MAMP\bin\mysql\bin -Password $password
```

Port 13306 must be free. The datadir must not exist:
`<clone>/migrations/mt4/private/mt5a-mamp-13306/data`.
On the current development computer this instance already exists: **do not run
CreateInstance or replay the bootstrap**. The public runner intentionally requires its own creation attestation and refuses
adopting an existing external instance; do not manufacture an instance.json marker.
VerifyOnly is for an instance created by this portable setup. No existing database is deleted or reset.

The setup verifies process executable/PID/listener, MySQL version, server UUID,
hostname, loopback bind, SQL port/datadir and DATABASE(). Hostname and absolute
paths are established on the new machine, not hardcoded to the old computer.
Port 3306, reparse points, datadir overlap with the principal server, populated
paths/databases, unexpected clients and transactions are refused. No fallback.
The principal server is not connected to or restarted. No Windows service is installed.

Initialization has networking disabled. Root receives the private password over
shared memory; TCP starts only after password verification and orderly initialization
shutdown. The technical er_test@localhost definer is created with a random password,
ACCOUNT LOCK and test-database-only privileges. No public default passwords or
human administrator memberships. Password transport uses SecureString and child
process environment, not CLI arguments, manifests or public files. Store it privately.

## Rebuilt schema

The consolidated `migrations/bootstrap/001_schema.sql` contains **metadata only**:
40 tables, 88 full trigger definitions, 118 FK, 164 indexes. It includes MT1/MT3/MT4,
security generation candidate-r3, IAM ledger, onboarding and MT-5D governance/recovery.
No private dump, application rows, users, password hashes or historical audit is used.

Tables are created first, then FK with checks enabled, then triggers ordered by
owner table/timing/event/ACTION_ORDER with each original SQL_MODE, charset,
collation and DEFINER. `schema-contract.json` supplies complete comparison metadata.
The MySQL dump SQL_MODE limitation is avoided by explicit creation contexts.
Only data-dependent AUTO_INCREMENT watermarks are normalized; column semantics remain.

After structural validation the setup creates only the technical Provisioning
MT3A_LEGACY_TEST holding/scope required by legacy test writers. This is not a real
Foundation or an administrator. Test scenario data is generated by SeedData.

Do not apply the historical migrations after bootstrap: their objects are already
included. In particular do not replay MT1/MT3/MT4, candidate-r3, iam-d, onboarding
or governance expand scripts. R1/R2 remain historical review evidence. Original
migration bytes/manifests are preserved; new artifacts use LF, historical files
retain their individually certified LF/CRLF via .gitattributes.

## Verification and failures

```powershell
./tools/setup-local-test-db.ps1 -MySqlBin C:\MAMP\bin\mysql\bin -VerifyOnly -Password $password
python tools/test_local_test_db.py
git check-ignore -v migrations/bootstrap/001_schema.sql
git diff --check
```

check-ignore must return exit 1/no match for public canonical SQL; private artifacts
must be ignored. Every bootstrap dependency has SHA256 checked before use.
VerifyOnly reads schema and integrity metadata without changing application data.
It compares all SHOW CREATE definitions and trigger contexts, all composite FK
relationships (zero orphans), and validators MT4A 7, MT4C 5, MT5B 6+2, IAM 4+2,
onboarding 5 and governance 5, each zero. No SET GLOBAL, FK disabling or trigger bypass.

The exclusive journal refuses replay after any attempted installation. On DDL failure,
stop and retain partial state: there is no global MySQL DDL rollback and no automatic
restore/repair. The runner requires all discovered tests executed and passed, with
private TRX/log output and synthetic fixture teardown through the existing guards.
Normal integration tests use 13306; other private ports are for independent schema
portability proofs and never weaken the fixture purge guards.

## Owner configuration

All rollout flags default false. Configure PlatformOperator public keys and a trusted
notification adapter explicitly as platform owner, outside Git. No production keys,
provider or real operator identities are created by setup. Recovery requires two
distinct authorized operators and remains closed otherwise. See
[authority and onboarding](../architecture/PLATFORM_OPERATOR_AND_ONBOARDING.md) and
[governance/recovery](../architecture/INSTITUTION_GOVERNANCE_AND_RECOVERY.md).

Private datadir, credentials, local configuration, backup bundles and sensitive logs
remain ignored. `VERSIONING_CANDIDATES.json` is the review list before an authorized
commit; existence on disk does not imply a file is already committed or on GitHub.
Old runners/reports may refer to private historical dumps; these are not dependencies
of this portable setup. Never use this test database for operational data.
